What {{name}} doesn’t catch

A security tool that claims to stop everything is either lying or a sandbox. {{name}} is neither. Here is where its view ends, so you can decide what else you need.

Limits every hook-based guard shares

  • Hooks are cooperative. They see what the agent declares. If an agent writes a script and runs it later, {{name}} sees python build.py, not what’s inside. Base64, string building and other obfuscation can get past pattern rules. Common tricks are caught by heuristics, not all of them.
  • Hooks must be running. An agent started with hooks disabled, or a Codex hook you haven’t trusted yet, isn’t checked. {{name}} watches the config files and warns you if its hooks disappear, but it can’t force an agent to load them. Agent bugs can skip hooks for some paths too (there are open Claude Code issues about certain subagent paths).
  • Some events aren’t covered. Hosted tools that run on the vendor’s servers (for example Codex’s web search) never pass through local hooks. Background sessions without a terminal may not fire hooks in some agents.
  • It isn’t a sandbox. Processes started by an allowed command run with your full permissions. For code you don’t trust, also use a container, a VM or a separate macOS user.
  • It doesn’t scan what the model writes. In the current release, secrets pasted into files or returned in tool output aren’t scanned. That’s on the roadmap.
  • Network rules are about intent, not packets. {{name}} spots commands that send secret files to a host. It doesn’t monitor network traffic.

When something fails

Agents treat a crashing hook differently. Claude Code and Codex let the action through if a hook errors, so {{name}}’s helper is written to always answer with an explicit decision. Cursor hooks are installed with failClosed, so a failure blocks. If the menu-bar app isn’t running, hard blocks still apply; see the FAQ for how questions are handled.

Found a gap that isn’t listed? If it’s a working way around a rule, report it privately on GitHub; bypass reports are the most useful thing you can send us. For anything else, open an issue or email {{contactEmail}}. We’ll add it here, fix it, or both.
